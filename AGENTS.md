# AGENTS.md: Authz

Authorization service for Bus 2.0: permission catalogue, company roles and members, and the authorization state it publishes to Redis for the APISIX gateway. See README.md; design in `docs/superpowers/specs/`.

## Commands

| Command | Purpose |
|---|---|
| `make tools` | Install pinned buf and protoc plugins into `./bin` |
| `make generate` | Regenerate `api/` from `proto/` (commit the result) |
| `make test` | Go tests (Postgres via testcontainers: needs Docker) |
| `make verify` | lint, test, template |
| `docker compose up -d --build` | Local Authz + Postgres on `shohoz` |

## Stack

uber **fx** for DI: each package owns a `var Module = fx.Module(...)` in its `module.go` (its providers and lifecycle hooks); `internal/ioc` only lists the modules and returns the `*fx.App`. Add a dependency in its package's module, then include the module in `ioc` if it is new. **Type safety:** every implementation carries a compile-time assertion (`var _ Iface = (*Impl)(nil)`), modules provide implementations as their interface (`fx.As`), and consumers depend on the narrowest interface they need, declared in the consumer and taken as constructor parameters (the consumer's module binds the concrete type to it with a private provider, `func(s *role.Service) Roles { return s }`) (`admin.Roles`, `internalapi.Companies`, `rolerepo.Repo`, `uow.Transactor`, `uow.Querier`, `cache.Publisher`, `health.Checker`, `idp.Client`, `events.Publisher`); health probes are a value group (`health.ProbeGroup`: the package owning a dependency contributes its probe, as `db` does). The list order is the start order: migrations (`db`), repositories (`repository`), the unit of work (`db/uow`), the services with Authz's own manifest seed (`service`), handler modules declaring their services (`handler/health`, `handler/admin`, `handler/internalapi`), then the router building the handlers and opening the listeners (`router`, last), **chi** for HTTP routing, **proto** as the API source of truth: three layers (spec `2026-10-09-handler-service-repository-design.md`): **handlers** (`internal/handler/*`, one package per proto service, transport only), **services** (`internal/service/<name>`: one package and one fx module per service, business rules only; `service/access` is the shared escalation rule), **repositories** (`internal/repository/<name>`: one package and one fx module per aggregate, SQL only; each owns its row types and its `Repo` interface). Services import repositories directly and run them through the unit of work (`internal/db/uow`), which carries the transaction (or the read replica) in the context: repositories run every query on `uow.Q(ctx)`. Errors live in `internal/apperror`; what is published to Redis in `internal/cache`. `service.Module` and `repository.Module` only list their packages' modules, served by **Vanguard** as Connect, gRPC, gRPC-Web and REST on one port per zone (h2c), pgx, goose, **go-redis** to publish to Redis.

## Invariants (do not break)

1. **The API is defined in proto.** Add or change an endpoint in `proto/`, run `make generate`, implement it in that service's handler package (`internal/handler/...`); business rules go in `internal/service/<name>`, SQL in `internal/repository/<name>`, never in a handler. No hand-written REST handlers. Health is `HealthService` (`GET /live`, `GET /ready`: the kubelet's probes).
2. **Two trust zones.** `AdminService` only on the public listener (trusts `X-Bus-*` from the gateway); `InternalService` only on the internal listener; `HealthService` only on the internal listener (the kubelet probes the internal port; the public port is the gateway's alone). Each handler module declares its service in one line, picking its listener: `router.Public(authzv1connect.NewAdminServiceHandler)` or `router.Internal(...)`; the implementation is provided as the generated handler interface (`fx.As`). These put a `router.Service` into the `vanguard_services` fx group; `router.New` takes them all through `router.Params` (`fx.In`) builds one handler per listener, and runs both listeners (`router.Module`, last in `ioc`: it opens the ports after every other start hook). `internal/ioc/routes_test.go` checks every service lands on its listener only. Each zone gets its own Vanguard transcoder; RPC paths go to it untouched, every other path is REST behind `apperror.REST`. Never wire a service into the other zone, and keep the NetworkPolicy in step with the ports.
3. **Every committed change to a role, permission, route, company status or member's roles is published to Redis** (`internal/cache`, `cache.Publisher`). The service reads what to publish inside its unit of work (`uow.UnitOfWork`) and writes it after commit; publishing is best effort (a failure is logged, never returned). Every boot resyncs (`service/resync`, after the manifest seed): it republishes the whole state from Postgres and deletes keys of what no longer exists, so a missed publish or a flushed Redis is repaired at the next boot. No locking: concurrent writes to the same key (or a write during the resync) can publish out of order until that entity next changes or the next boot. The Redis key layout (`internal/cache`) is a contract with `../APISIX`: change both together.
4. **Tenant scope.** Every role, member and invitation query is scoped by the caller's `company_id`; `member_roles` has composite foreign keys so a cross-company assignment cannot exist.
5. **Escalation rule.** Nobody creates, edits, deletes, assigns or removes a role whose permissions they don't hold (read fresh from the database, never from the token).
6. **Deny by default.** Unknown or deprecated routes (and deprecated permissions) are not published; the gateway denies what it does not find.
7. **Domain errors are transport-neutral** (`apperror.Kind` + a stable code, `internal/apperror`); repositories return `apperror.ErrNotFound` / `apperror.ErrDuplicate` (`apperror.FromPG`) or raw errors, services return `apperror.Fail(...)`, and handlers return errors untouched (they raise their own with `apperror.Fail` too). The one place errors are formatted is `apperror.Interceptor` (in every service's handler options): a domain error becomes its Connect code with the code as `ErrorInfo.reason`, a Connect error passes through, anything else is logged and becomes `Internal` without details; `apperror.REST` then shapes REST bodies. Don't build Connect errors outside `apperror`.
8. **The chart never creates secrets.**
9. **Migrations run at boot**, before anything is served (`db.Module`, early in `internal/ioc`). There is no separate migrate command; a migration must be safe to apply while older replicas are still serving (expand, then contract).
10. **Authorization versions are never reused.** `members.authz_version` comes from the global `authz_versions` sequence; a new value on every role assignment change. Never reset it per user.

## Gotchas

- Authz refuses to boot while Redis is unreachable (the boot resync); `/ready` fails while Redis or Postgres is down, `/live` never checks them.
- Invitations are delivered by the IdP (`../IdP`, `/api/internal/invitations`); if that call fails, the invitation is deleted and the admin gets `UNAVAILABLE`.
- REST JSON clients get REST; a JSON POST to an RPC path needs `Connect-Protocol-Version: 1` (real Connect clients send it), or Vanguard treats it as REST.
- Local compose needs `../Infra` up first (its Redis, `infra-redis`); Authz restarts until it is.
- Two Postgres pools (`db.WritePool`, `db.ReadPool`; `AUTHZ_DATABASE_READ_URL` defaults to the primary). Units of work and migrations use the primary. Repositories run every query on `uow.Q(ctx)`: the transaction inside a unit of work, **the read replica outside one**, lag accepted (a read right after a write may miss it: `role.Create` returning the new role, `Claims` right after signup or acceptance). A write outside a unit of work therefore fails (the replica is read-only, and so is the tests' read pool, `testdb.ReadOnly`). A nested `UnitOfWork` joins the outer transaction.
- Events are published after commit, best effort (no outbox): a Kafka outage loses them (logged).
